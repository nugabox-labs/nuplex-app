# 플랫폼별 확인 목록

`docs/TESTING.md` 는 **어떻게** 확인하는지를 적는다(계정 · 주소 붙이는 법 · 푸시 보내는 법).
여기는 **무엇을 확인했는지**를 플랫폼별로 남긴다.

| 파일 | 대상 |
| --- | --- |
| [`ios.md`](ios.md) | iOS — 시뮬레이터 · 실기기 |
| [`android.md`](android.md) | Android — 에뮬레이터 · 실기기 |

## 쓰는 법

1. 셸을 고쳤거나 웹을 배포하기 전에 해당 파일을 훑는다.
2. **확인한 것만 체크한다.** 빌드가 통과한 것은 확인이 아니다(`docs/plan/README.md` 규칙 4).
3. 체크 옆에 **무엇을 어떻게 봤는지** 한 줄 남긴다. 로그 한 줄이면 로그를 붙인다.
4. 못 한 것은 지우지 말고 `미검증` 과 이유를 남긴다.
5. 실패하면 `실패:` 로 시작하는 줄을 달고, 고친 뒤 근거와 함께 다시 체크한다.

## 표기

- `[ ]` 안 함 · `[x]` 확인함 · `[-]` 이 플랫폼에는 해당 없음
- ★ = **실기기가 필요하다.** 시뮬레이터/에뮬레이터로는 결론이 안 난다
- 회차마다 덮어쓰지 말고 **날짜와 빌드를 머리에 적고** 이어 쓴다

## 왜 나눴나

두 플랫폼의 실패 지점이 다르다. Android 는 알림 채널과 인텐트 extra 에서 깨지고,
iOS 는 델리게이트 가로채기와 안전영역에서 깨졌다. 한 파일에 섞으면
"어느 쪽에서 본 것인지" 가 흐려져 같은 버그를 두 번 만난다.
