# 작업 기록

기억이나 대화 맥락에 의존하지 않기 위한 진행 상황 기록. 세션이 끊겨도 여기만 읽으면
"무엇이 끝났고 무엇이 남았는지" 를 복원할 수 있어야 한다.

```
docs/plan/
├── active/   진행 중이거나 아직 시작하지 않은 작업
└── done/     끝난 작업. 무엇을 왜 그렇게 했는지와 검증 결과를 남긴다
```

## 규칙

1. **작업을 시작하기 전에** `active/` 에 파일을 만든다. 파일명은 `phase-N-주제.md`.
2. 진행하면서 체크박스를 갱신한다. 도중에 알게 된 사실(특히 명세와 다른 점)은
   그때그때 적는다. 나중에 몰아서 쓰면 반드시 빠진다.
3. 끝나면 **검증 결과와 커밋 해시를 적고** `done/` 으로 옮긴다.
4. 검증하지 않은 것은 완료로 옮기지 않는다. 실기기가 필요해 미룬 항목은
   `done/` 문서 안에 "미검증" 으로 남긴다. 빌드 통과는 동작 확인이 아니다.
5. 사람이 해야 하는 작업(스토어 계정, 콘솔 설정 등)은 `active/` 에 그대로 두고
   무엇을 기다리는지 명시한다.

## 현황

| | 문서 |
| --- | --- |
| 완료 | `done/` 참고 |
| 진행 중 | `active/` 참고 |

설계 명세 원본은 대화로 전달받은 `nuplex-app-design-prompt.md` 이며, 그와 달라진
결정은 `docs/ADR-*.md` 에 따로 기록한다.
